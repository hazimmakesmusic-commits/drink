# THE SIXTH FRIEND

An AI-powered sixth friend that randomly interrupts your hangout with bizarre, surreal,
interactive events. Everyone joins from their own phone. The app stays quiet — then suddenly
**ANOMALY DETECTED**.

Not a party-game collection: an *entity* in the room with a personality, a memory of the night,
and a living, psychedelic world as its interface.

```
GROUP TALKS → APP IS QUIET → SUDDEN INTERRUPTION → ABSURD EVENT → GROUP REACTS
   → AI COMMENTARY → APP DISAPPEARS → … another one, whenever it feels like it
```

## Easiest: put it online (no installs, works on any phone)
1. Fork/push this repo to GitHub, then on https://render.com choose **New + → Blueprint** and pick the repo
   (`render.yaml` is already set up; free plan).
2. When it finishes you get a URL like `https://sixth-friend.onrender.com`. Open it on every phone — no Wi-Fi
   or firewall fiddling, and the QR code works. (Free plan sleeps when idle; first load takes ~30s.)

## Run it on your own computer
Double-click `start.bat` (Windows) or `start.command` (Mac), or:

```bash
npm install
npm start            # http://localhost:3000
npm run dev          # PACE=fast: short gaps between events, for demos
npm test             # unit + realtime integration tests (bots play full sessions)
```

Open it on a phone (same Wi-Fi: `http://<your-ip>:3000`) — one person taps **CREATE SESSION**,
the others scan the QR / type the 4-letter code. 2–10 players, 5–6 is the sweet spot.

Optional environment (`.env.example`):

| var | meaning |
|---|---|
| `ANTHROPIC_API_KEY` | Turns on the LLM host (dialogue, commentary, novel events). Without it the built-in content engine runs everything and the app is still fully playable. |
| `ANTHROPIC_MODEL` | Default `claude-haiku-5-5` (low latency). |
| `PACE=fast` | Shrinks the quiet gaps (for demos). |
| `DEV_TOOLS=1` | Host menu can force any specific event. |

## How it works

```
server/
  index.js        HTTP + WebSocket + QR; per-socket rate limit
  session.js      A hangout: players, settings, memory, director loop (quiet → event → commentary)
  director.js     WHEN the AI interrupts and WHAT happens (rhythm, weights, memory-driven callbacks)
  engine.js       EventRun: runs a list of primitive steps, owns timers/results/vars
  primitives.js   The interaction primitives (say, secret, point, choose, type, tap, hold, shake,
                  trap, draw, sync, reveal, verdict). New experiences = new *combinations*.
  events/library.js  27 events, 100% data (no per-event code)
  schema.js       Validates/normalises any event (library or AI-made); LLM tool schema
  host.js         The AI host: persona, generated "slots", commentary, novel-event creation
  personas.js     ALIEN, CHAOS, COSMIC, MENACE, ORACLE, GREMLIN, PSYCHEDELIC, VOID
  originality.js  Anti-cliché engine (scores every event, rejects classic party-game shapes)
  safety.js       Content guard rails for AI output and player text
  memory.js       Session memory (dies with the session — nothing persisted between sessions)
  content.js      Offline word banks / generators (used when no LLM key or on LLM failure)
public/           Mobile-first client, no build step (vanilla ES modules + canvas)
  js/world.js     The living background: 14 canvas "worlds" (planet, portal, eye, black hole,
                  glitch, tunnel, court, dream, void, storm, sun…) with crossfades + FX
  js/stage.js     Public stage + private per-phone panels for each primitive
```

**The AI controls the content; the app controls the UI.** An event is JSON — a list of steps
built from fixed primitives — so the model can invent new events without ever generating UI:

```json
{ "title": "THE MOON AUDIT", "world": "court", "intensity": 3, "originality": 9,
  "steps": [
    { "t": "say",   "text": "{subject} has been selected for a moon audit." },
    { "t": "tap",   "mode": "mash", "prompt": "Polish the moon. Tap.", "duration": 8 },
    { "t": "point", "prompt": "Who polished it suspiciously? Point.", "duration": 15 },
    { "t": "verdict", "slot": "conclusion", "title": "AUDIT RESULT" } ] }
```

Text can use `{subject} {leader} {last} {p1}…`, step results (`{stepid.top}`), and generated slots
(`{{crime}}`, `{{evidence}}`, `{{creature}}`, `{{readout}}`…). Slots are generated by the LLM when a
key is set, otherwise by `content.js`.

### What makes it feel like a sixth person
* **Rhythm** – quiet gaps are drawn from a skewed distribution: sudden bursts (≈16%), suspiciously
  long silences (≈12%), and intensity-scaled normal gaps. Whispers appear during the quiet.
* **Session memory** – who was chosen, who won/lost, who stayed quiet, running jokes, prophecies,
  aliases. It triggers callbacks: pick the same player 3× and **THE COUNCIL HAS SPOKEN** fires;
  predictions typed in *THE LEDGER OF FUTURES* are *audited* a few events later; *NAMING CEREMONY*
  makes the AI call everyone by new names for three events.
* **Anti-cliché engine** – every event is scored; Would-You-Rather / Truth-or-Dare / trivia /
  icebreaker / drinking-game shapes are rejected (`test/library.test.js`).
* **Visuals are interaction** – e.g. *DO NOT TOUCH*: touching the red planet explodes the interface
  into a different world for everyone.

### Safety
Absurd, never dangerous. AI output (slots, commentary, whole events) passes `safety.js`
(no alcohol/drug/driving/climbing/fire/stunt/sexual/violence/self-harm instructions, profanity
filter) and falls back to the built-in engine if it fails. Player-typed text is cleaned and
profanity-masked. Roast level (0–3) is host-controlled and limited to harmless choices/reflexes.
18+ confirmation at signup. Not marketed to any specific substance use.

## V1 scope & honest limits
* Web app (installable, mobile-first) instead of React Native/Flutter — fastest way to prove the
  group experience; the server/event/AI layer is client-agnostic.
* Accounts are a tiny JSON-file store (name, face, 18+ flag). Swap for Supabase/Firebase auth.
* LLM paths are covered by stubbed-API tests; they have **not** been exercised against the live API
  in this repo's CI. Camera/microphone primitives, persistent friend profiles, long-term memory,
  subscriptions and a TV app are intentionally out of V1.
* Phone sensors (shake) need a real device; iOS asks for motion permission via an on-screen button.
  A tap fallback is always present.

## Success metric
*Would this group voluntarily start another session?* — not downloads, not minutes.
